## 0.多线程

### 是什么：

多线程是指程序可以在同一时间内处理多个任务，每个任务在单独的执行路径（线程）中运行，各自独立执行。

### 为什么：

#### （1）为什么要使用多线程？

想象一个餐厅的运营流程：餐厅接待顾客时，多个顾客同时点餐、用餐和结账，彼此之间是**相互独立的任务**。

1. 每个顾客的服务是独立的，可以并行处理。
2. 服务员、厨师、收银员各自独立执行任务，并且可以同时服务多个顾客。

------

**单线程实现模式：由一个线程依次执行每个任务，必须前一个任务执行完毕才能执行下一个任务**

如果只有一个线程（一个服务员）负责所有事情，每次只能处理一个顾客：

- 先接待顾客 1 点单，等待厨师做好菜再上菜；
- 顾客 1 完成后，再接待顾客 2；

单线程的实现：

```java
public class SingleThreadRestaurant {
    public static void main(String[] args) {
        System.out.println("接待顾客 1 点单...");
        System.out.println("为顾客 1 准备菜品...");
        System.out.println("顾客 1 享用餐点...");
        System.out.println("顾客 1 结账...");
        
        System.out.println("接待顾客 2 点单...");
        System.out.println("为顾客 2 准备菜品...");
        System.out.println("顾客 2 享用餐点...");
        System.out.println("顾客 2 结账...");
    }
}

```

**多线程实现模式：由多个线程同时执行多个任务，彼此互不干扰**

如果有多个线程（多个服务员），每个顾客的服务由独立线程处理，可以同时进行：

- 顾客 1 和顾客 2 点餐、用餐和结账的任务互不干扰。
- 服务员、厨师等可以同时处理多个顾客，提升效率。

多线程实现：

```java
class CustomerTask implements Runnable {
    private String customerName;

    public CustomerTask(String customerName) {
        this.customerName = customerName;
    }

    @Override
    public void run() {
        System.out.println(customerName + " 点单中... (线程: " + Thread.currentThread().getName() + ")");
        try {
            Thread.sleep(1000); // 模拟点单时间
            System.out.println(customerName + " 享用餐点中... (线程: " + Thread.currentThread().getName() + ")");
            Thread.sleep(2000); // 模拟用餐时间
            System.out.println(customerName + " 结账中... (线程: " + Thread.currentThread().getName() + ")");
        } catch (InterruptedException e) {
            e.printStackTrace();
        }
    }
}




public class MultiThreadRestaurant {
    public static void main(String[] args) {
        Thread customer1 = new Thread(new CustomerTask("顾客 1"));
        Thread customer2 = new Thread(new CustomerTask("顾客 2"));
        Thread customer3 = new Thread(new CustomerTask("顾客 3"));

        customer1.start();
        customer2.start();
        customer3.start();
    }
}
```



### 怎么办：

#### （1）如何理解多线程的同时执行？

- 在多核`cpu`系统中，同时执行就是字面意思，每个`cpu`执行一个线程任务，多个线程任务可以在同一时间分别运行；
- 在单核`cpu`系统中，同时执行指的是广义上的同时执行，即在一段微小时间内继续进行时间片的划分，`cpu`在一个时间片内先执行一个线程任务然后在另一个时间片内执行另一个线程任务，在广义上看这些线程任务好像是在同一时间运行的（但其实不是，只是时间片的划分太细了以及`cpu`的处理速度太快了，人看不出来差别）

#### （2）并行与并发的区别？

- 并行：指的就是多核`cpu`系统中多个任务同时执行
- 并发：指的就是单核`cpu`系统中多个任务看似同时执行其实是交替执行

#### （3）一般所谓的多线程指的是并行的线程还是并发的线程呢？

**多线程**既可以指并行，也可以指并发，具体取决于系统的硬件和运行环境：

- 在 **多核 CPU** 上，多线程可以实现**并行执行**（Parallelism）。
- 在 **单核 CPU** 上，多线程通过时间片轮转实现**并发执行**（Concurrency）。

**总结：**

- **广义的多线程**更==强调线程之间的**任务分离和独立性**，而不严格限定是并行还是并发==。
- 在实际开发中，“多线程”通常指的是任务之间可以**独立运行**，具体是并行还是并发则取决于硬件支持。

#### （4）Java 中的多线程是指的并行还是并发？

Java 的多线程机制是**并发模型**，但在多核 CPU 上可以实现**并行执行**。

1. **Java 多线程的核心机制：**
   - Java 的多线程依赖于操作系统的线程调度机制。
   - 在单核 CPU 上，Java 的多线程通过时间片轮转实现并发。
   - 在多核 CPU 上，Java 可以将不同线程分配到不同的核心上，从而实现真正的并行。
2. **Java 的设计初衷：**
   - Java 的多线程设计并不要求一定实现物理上的并行，而是强调逻辑上的并发。
   - 因此，Java 多线程的本质是**并发模型**。

#### （5）并发模式下的多线程是如何提高效率的呢？

前面我们说过在多核`cpu`的并行系统下多个线程任务同时执行这可以提高效率这点很好理解，但是在单核`cpu`的并发系统下多线程如何提高效率呢，在任意一个时间片明明都只有一个线程在执行，这样即使多个线程之间来回切换也没法节约单个线程任务的处理时间啊？

因为单个线程任务的总时间组成包括：任务的处理时间（`cpu`处理的时间）+ 等待时间（`io`操作的时间），在单核`cpu`的并发系统下多线程确实没法节约单个任务的处理时间但是却可以节约单个任务的等待时间，比如当A线程任务进入等待的时候此时用不到`cpu`就可以切换到B线程任务的计算（在单线程模式下`cpu`空闲也只能在那里干等）。举例如下：

**一个客服处理多个电话咨询：**

假设一个客服（**单核 CPU**）需要处理多个客户的电话咨询任务。每个电话咨询的流程包括以下两步：

1. **客服回答问题**（CPU 计算任务）。
2. **等待客户记录或回复**（I/O 等待任务）。

因为只有一个客服（即单核 CPU），客服不可能同时与多个客户对话，但在 **客户记录或回复时**，客服可以短暂地暂停当前对话，去接听其他客户的电话。

------

1. ==单线程处理电话咨询==

单线程的客服只能按顺序处理电话任务：

```java
public class SingleThreadCallCenter {
    public static void main(String[] args) {
        for (int i = 1; i <= 5; i++) {
            System.out.println("正在回答客户 " + i + " 的问题...");
            try {
                Thread.sleep(1000); // 模拟回答问题需要的时间
            } catch (InterruptedException e) {
                e.printStackTrace();
            }

            System.out.println("客户 " + i + " 正在记录答案...");
            try {
                Thread.sleep(2000); // 模拟客户记录答案的时间
            } catch (InterruptedException e) {
                e.printStackTrace();
            }
        }

        System.out.println("所有客户咨询完成！");
    }
}
```

- 每个客户的问题必须依次处理，后面的客户需要等前面的客户咨询完成后才能接通。
- 总耗时：(1+2)×5=15 秒



2. ==单核多线程下的并发模式处理电话咨询==

单核 CPU 上的多线程行为：客服在等待一个客户记录答案时，可以暂时挂起当前任务，转而接听下一个客户的电话。虽然是单核 CPU，但通过时间片轮转，所有任务交替运行，最终提高效率。

```java
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;

public class MultiThreadCallCenter {
    public static void main(String[] args) {
        ExecutorService executor = Executors.newFixedThreadPool(5); // 线程池允许并发 5 个线程
        for (int i = 1; i <= 5; i++) {
            int customer = i;
            executor.execute(() -> {
                System.out.println("正在回答客户 " + customer + " 的问题...");
                try {
                    Thread.sleep(1000); // 模拟回答问题
                } catch (InterruptedException e) {
                    e.printStackTrace();
                }

                System.out.println("客户 " + customer + " 正在记录答案...");
                try {
                    Thread.sleep(2000); // 模拟记录时间
                } catch (InterruptedException e) {
                    e.printStackTrace();
                }
            });
        }
        
        executor.shutdown();       
        System.out.println("所有客户咨询完成！");
    }
}
```

**运行机制：如何节约时间？**

通过时间片切换隐藏等待时间：

1. 线程 1 的任务：
   - 执行回答问题（1 秒）。
   - 进入记录答案阶段（I/O 等待），此时 CPU 切换到线程 2。
2. 线程 2 的任务：
   - 执行回答问题（1 秒）。
   - 进入记录答案阶段，CPU 切换到线程 3。
3. 线程切换的效果：
   - 当所有线程都完成了“回答问题”阶段（5 秒内），I/O 阶段可能已经部分完成。
   - 多线程隐藏了每个线程的 I/O 等待时间，使得总时间显著减少。

- 客服会在客户记录答案时，快速切换到下一个客户咨询。

- 总耗时接近 **7 秒**，远低于单线程的 15 秒。





## 1.实现多线程

### 1.1简单了解多线程【理解】

是指从软件或者硬件上实现多个线程并发执行的技术。
具有多线程能力的计算机因有硬件支持而能够在同一时间执行多个线程，提升性能。

![01_简单了解多线程](.\img\01_简单了解多线程.png)

### 1.2并发和并行【理解】

+ 并行：在同一时刻，有多个指令在多个CPU上同时执行。

  ![02_并行](.\img\02_并行.png)

+ 并发：在同一时刻，有多个指令在单个CPU上交替执行。

  ![03_并发](.\img\03_并发.png)

### 1.3进程和线程【理解】

- 进程：是正在运行的程序

  独立性：进程是一个能独立运行的基本单位，同时也是系统分配资源和调度的独立单位
  动态性：进程的实质是程序的一次执行过程，进程是动态产生，动态消亡的
  并发性：任何进程都可以同其他进程一起并发执行

- 线程：是进程中的单个顺序控制流，是一条执行路径

  ​	单线程：一个进程如果只有一条执行路径，则称为单线程程序

  ​	多线程：一个进程如果有多条执行路径，则称为多线程程序

  ​	![04_多线程示例](.\img\04_多线程示例.png)

### 1.4实现多线程方式一：继承Thread类【应用】

- 方法介绍

  | 方法名       | 说明                                                         |
  | ------------ | ------------------------------------------------------------ |
  | void run()   | 在线程开启后，此方法将被调用执行（方法内部就是我们定义的线程要执行的操作） |
  | void start() | 使此线程开始执行，Java虚拟机会调用run方法()                  |

- 实现步骤
  - 定义一个类MyThread继承Thread类
  - 在MyThread类中重写run()方法
  - 创建MyThread类的对象
  - 调用start方法启动线程




#### notes：`Thread`中的`start`方法和`run`方法的区别？

- `start`方法：启动一个线程，通过`start`方法启动一个线程后会去自动执行线程里面的`run`方法从而实现线程要执行的操作，这个过程不同于我们直接调用`run`方法（直接调用`run`方法的话我们就是在当前线程下去调用了一个普通的方法执行里面的操作），而调用`start`方法的话就是在当前线程之外另外创建了一个线程让新创建的线程去执行`run`方法（新创建的线程不会影响当前的线程）
- `run`方法：线程要执行的操作



- 代码演示

  ```java
  public class MyThread extends Thread {
      @Override
      public void run() {
          for(int i=0; i<100; i++) {
              System.out.println(i);
          }
      }
  }
  
  
  public class MyThreadDemo {
      public static void main(String[] args) {
          MyThread my1 = new MyThread();
          MyThread my2 = new MyThread();
  
          /**
          直接调用线程的run方法是不对的，此时并没有创建新的线程。
          my1.run();
          my2.run();
          */      
  
          //void start() 导致此线程开始执行; Java虚拟机调用此线程的run方法
          my1.start();
          my2.start();
      }
  }
  ```

- 两个小问题

  - 为什么要重写run()方法？

    因为run()是用来表示我们希望线程要执行的操作

  - run()方法和start()方法的区别？

    run()：封装线程执行的代码，如果直接调用的话相当于普通方法的调用

    start()：启动线程；然后由JVM调用此线程的run()方法





### 1.5实现多线程方式二：实现Runnable接口【应用】

- Thread构造方法

  | 方法名                               | 说明                                     |
  | ------------------------------------ | ---------------------------------------- |
  | Thread(Runnable target)              | 创建一个新的Thread对象                   |
  | Thread(Runnable target, String name) | 创建一个新的Thread对象，并给它命名为name |

- 实现步骤

  - 定义一个类MyRunnable实现Runnable接口
  - 在MyRunnable类中重写run()方法，在其中声明我们要线程执行的操作
  - 创建MyRunnable类的对象
  - 创建Thread类的对象，把MyRunnable对象作为构造方法的参数
  - 启动线程

- 代码演示

  ```java
  public class MyRunnable implements Runnable {
      @Override
      public void run() {
          for(int i=0; i<100; i++) {
              System.out.println(Thread.currentThread().getName()+":"+i);
          }
      }
  }
  
  
  public class MyRunnableDemo {
      public static void main(String[] args) {
          //创建MyRunnable类的对象
          MyRunnable my = new MyRunnable();
  
          /*
          创建Thread类的对象，把MyRunnable对象作为构造器的形参
          这里Thread的构造器有两种形式：
          Thread(Runnable target)和Thread(Runnable target, String name)
          分别举例：        
          Thread t1 = new Thread(my);
          Thread t2 = new Thread(my);
          */
          Thread t1 = new Thread(my,"坦克");
          Thread t2 = new Thread(my,"飞机");
  
          //启动线程
          t1.start();
          t2.start();
      }
  }
  ```





### 1.6实现多线程方式三: 实现Callable接口【应用】

![image-20250531214620343](./%E5%A4%9A%E7%BA%BF%E7%A8%8B01.assets/image-20250531214620343.png)

+ 方法介绍

  | 方法名                           | 说明                                                         |
  | -------------------------------- | ------------------------------------------------------------ |
  | V call()                         | 定义我们希望线程要执行的操作，并将操作结果返回，如果无法计算结果，则抛出一个异常 |
  | FutureTask(Callable<V> callable) | 用于接收call方法执行的结果，并且将callable接口的对象包装成runnable接口的对象 |
  | V get()                          | 如有必要，等待计算完成，然后获取其结果                       |

+ 实现步骤

  + 定义一个类MyCallable实现Callable接口
  + 在MyCallable类中重写call()方法，在call方法中定义我们希望线程执行的操作，并将操作结果返回，如果无法计算结果的话则抛出异常
  + 创建MyCallable类的对象
  + 创建FutureTask类的对象，把MyCallable对象作为构造方法的参数
  + 创建Thread类的对象，把FutureTask对象作为构造方法的参数
  + 启动线程
  + 再调用get方法，就可以获取线程结束之后的结果。



#### notes：`Callable`接口中的`call`方法与`Runnable`接口中的`run`方法有什么异同？

- 相同点：

​	`call`方法和`run`方法里面定义的都是我们希望线程执行的操作

- 不同点：

  - `run`方法：没有返回值

  - `call`方法：有返回值，返回线程执行的结果，如果线程操作无法计算结果的话会返回异常，如果我们希望线程的执行一定得返回一个结果的话那么只能通过`call`方法实现

#### notes：为什么要用`FutureTask`类的对象去接收Callable接口的对象？

这里`FutureTask`对象有两个作用：

- 接收`call`方法执行的结果，方便后续调用线程的执行结果
- 将`Callable`接口的对象包装成`Runnable`接口的对象，我们知道`Thread`类的构造器有两种形式：
  - Thread(Runnable target)
  - Thread(Runnable target, String name)

两种形式都得接收`Runnable`接口的对象没法接收`callable`接口的对象。所以我们需要通过`FutureTask`对象将`callable`接口的对象包装成`runnable`接口的对象。



#### notes：三种实现方式的对比

+ 实现Runnable、Callable接口
  + 好处: 扩展性强，实现该接口的同时还可以继承其他的类
  + 缺点: 编程相对复杂，不能直接使用Thread类中的方法
+ 继承Thread类
  + 好处: 编程比较简单，可以直接使用Thread类中的方法
  + 缺点: 可以扩展性较差，不能再继承其他的类





### 1.7设置和获取线程名称【应用】

- 方法介绍

  | 方法名                        | 说明                 |
  | -------------------------- | ------------------ |
  | void  setName(String name) | 将此线程的名称更改为等于参数name |
  | String  getName()          | 返回此线程的名称           |
  | Thread  currentThread()    | 返回对当前正在执行的线程对象的引用  |

- 代码演示

  ```java
  public class MyThread extends Thread {
      public MyThread() {}
      public MyThread(String name) {
          super(name);
      }
  
      @Override
      public void run() {
          for (int i = 0; i < 100; i++) {
              System.out.println(getName()+":"+i);
          }
      }
  }
  
  
  
  
  public class MyThreadDemo {
      public static void main(String[] args) {
          MyThread my1 = new MyThread();
          MyThread my2 = new MyThread();
  
          /*
          演示线程的setName方法：
  ```

### 1.8线程休眠【应用】

#### 是什么：

线程休眠是指强行暂停线程的执行，线程在休眠期间会释放 CPU，但不释放已占用的资源（如锁）。线程休眠后，系统不会主动中断它，而是等待指定的休眠时间结束后，线程进入**就绪状态**，等待 CPU 调度重新运行。

#### 为什么：

##### （1）为什么要使用线程休眠？

**控制线程执行的节奏**：

- 通过休眠让线程在一段时间后执行特定任务，例如定时任务或延迟处理。

**模拟耗时操作**：

- 在测试或开发中，休眠可以用来模拟网络请求、文件 I/O 等耗时操作。

**避免频繁操作**：

- 在循环中加入休眠，避免线程高频率运行导致资源占用过多。

**让其他线程有机会运行**：

- 当多个线程运行时，休眠可以释放 CPU 资源，让其他线程有机会执行。

#### 怎么办：

##### （1）如何实现线程的休眠？

在 Java 中，线程休眠通过 `Thread.sleep()` 方法实现。

+ 相关方法

  | 方法名                            | 说明                       |
  | ------------------------------ | ------------------------ |
  | static void sleep(long millis) | 使当前正在执行的线程停留（暂停执行）指定的毫秒数 |

+ 代码演示

  ```java

      }
  }
  ```





### 1.9线程优先级【应用】

- 线程调度

  - 两种调度方式
    - 分时调度模型：所有线程轮流使用 CPU 的使用权，平均分配每个线程占用 CPU 的时间片
    - 抢占式调度模型：优先让优先级高的线程使用 CPU，如果线程的优先级相同，那么会随机选择一个，优先级高的线程获取的 CPU 时间片相对多一些（注意这里说的是优先级高的线程获得时间片的概率更大并不是说优先级高的线程一定会获得时间片）

  - 随机性

### 1.10守护线程【应用】

#### 是什么：

守护线程（Daemon Thread）是 Java 中的一种特殊线程，用于在后台执行一些辅助任务。它的生命周期依赖于**非守护线程**（即主线程或普通线程）。当所有非守护线程都执行完毕时，守护线程会自动终止，即使它的任务尚未完成。

#### notes：主线程是什么？

在任何 Java 程序中，**主线程**是由 JVM 自动创建并启动的第一个线程，它负责执行 `main` 方法中的代码。

**主要特点**：

1. **由 JVM 启动**：
   - 每个 Java 程序都从一个 `main` 方法开始。`main` 方法是程序的入口点，当 JVM 启动程序时，JVM 会自动创建一个线程来执行 `main` 方法中的代码，这个线程就是主线程。
2. **启动其他线程**：
   - 主线程可以通过调用 `Thread` 或 `Runnable` 来启动其他线程。主线程和其他线程可以并发执行。
3. **程序结束条件**：
   - 在 Java 中，当 **所有非守护线程**（包括主线程）执行完毕后，程序才会退出。如果主线程结束，且其他线程是守护线程，它们会被自动终止，程序整体会退出。
4. **生命周期**：
   - 主线程的生命周期从 `main` 方法开始，到 `main` 方法结束为止。当主线程执行完 `main` 方法中的代码时，主线程会结束。此时，程序会终止，除非有其他非守护线程正在运行。

#### 为什么：

##### （1）为什么要使用守护线程？

守护线程的主要目的是让程序能够在后台自动执行一些**非核心的**、**辅助性**的任务，而不需要用户或主线程干预。守护线程的生命周期与主线程（非守护线程）紧密相关，当所有非守护线程结束时，守护线程也会自动终止。

**示例场景：**

- **定时任务**：例如，定期清理缓存、定期检查更新等操作。
- **日志记录**：后台记录应用程序的日志文件。
- **网络监听**：持续监听网络连接或消息，但不影响主线程的执行。

#### 怎么办：

##### （1）如何使用守护线程？

- 相关方法

  | 方法名                        | 说明                                   |
  | -------------------------- | ------------------------------------ |
  | void setDaemon(boolean on) | 将此线程标记为守护线程，当运行的线程都是守护线程时，Java虚拟机将退出 |

**线程类型**：

- `t1` ("女神1号") 是一个普通线程。
- `t2` ("女神2号") 是一个普通线程。
- `t3` ("备胎") 被设置为 **守护线程**，通过调用 `t2.setDaemon(true)` 实现。

**守护线程特性**：

- 守护线程会在所有非守护线程（普通线程，这里就是`t1线程`、`t2线程`）结束后自动终止，不管其任务是否完成。
- 这里，`t3线程` 的运行依赖于 `t1、t2线程` 的生命周期。一旦 `t1、t2线程` 执行完毕，`t3` 将被强制终止。

**运行逻辑**：

- `t1和t2` 在其 `run()` 方法中打印 10 次，计数从 `0` 到 `9`。
- `t3` 在其 `run()` 方法中打印 100 次，计数从 `0` 到 `99`。
- 因为 `t3` 是守护线程，**它可能不会打印完 100 次，就会因为 `t1、t2` 的结束而终止运行**。

**线程调度**：

- `t1` 、 `t2` 和`t3`的执行顺序由操作系统的线程调度器决定，因此打印输出可能会交替出现。

- 代码演示

  ```java
  public class MyThread1 extends Thread {
      @Override
      public void run() {
          for (int i = 0; i < 10; i++) {
              System.out.println(getName() + "---" + i);
          }
      }
  }
  
  
  
  public class MyThread2 extends Thread {
      @Override
      public void run() {
          for (int i = 0; i < 100; i++) {
              System.out.println(getName() + "---" + i);
          }
      }
  }
  
  
  
  public class Demo {
      public static void main(String[] args) {
          MyThread1 t1 = new MyThread1();
          MyThread2 t2 = new MyThread2();
          MyThread2 t3 = new MyThread2();
  
          t1.setName("女神1号");
          t2.setName("女神2号");
          t3.setName("备胎");

          //当普通线程t1和t2执行完之后,那么守护线程也没有继续运行下去的必要了.

          t2.start();
          t3.start();
      }
  }
  ```





### 1.11出让线程

#### 是什么：

在多线程编程中，**“出让线程”**是指当前线程主动放弃 CPU 的执行权，使其他线程有机会获得 CPU 时间片并执行，这里当前线程放弃了`cpu` 时间片以后会和其他线程一起重新竞争并不是说其他线程一定会获得时间片。

#### 为什么：

##### （1）为什么要使用出让线程？

1. 公平竞争 CPU 时间片

在多线程环境中，如果某个线程执行任务的时间过长，其他线程可能会因无法获得 CPU 时间片而长时间处于等待状态。通过主动出让线程（如使用 `Thread.yield()`），当前线程可以让出 CPU，使其他线程有机会运行，避免某些线程被长时间饿死。

2. 避免线程优先级的不公平竞争

在一些操作系统中，线程优先级可能导致高优先级线程长时间占用 CPU，而低优先级线程被饿死。通过在高优先级线程中使用出让机制，可以改善这种不公平竞争，让低优先级线程有机会运行。

#### 怎么办：

##### （1）如何使用出让线程？

- `Thread.yield()`方法

  - `Thread.yield()` 是一个静态方法，表示当前线程主动向线程调度器发出提示，表明它愿意放弃当前的 CPU 时间片，让同优先级的其他线程有机会运行。

  - 当前线程进入就绪（Runnable）状态，不会进入阻塞（Blocked）或等待（Waiting）状态。

  - 具体哪个线程获得执行权由线程调度器决定（这取决于操作系统的调度策略）。

  - 如果没有其他线程或没有合适的线程可以运行，当前线程可能会立即重新获取 CPU 时间片并继续执行。

```java
public class YieldExample {
    public static void main(String[] args) {
        Thread t1 = new Thread(() -> {
            for (int i = 0; i < 5; i++) {
                System.out.println("Thread 1: " + i);
                Thread.yield(); // 主动出让 CPU
            }
        });

        Thread t2 = new Thread(() -> {
            for (int i = 0; i < 5; i++) {
                System.out.println("Thread 2: " + i);
            }
        });

        t1.start();
        t2.start();
    }
}
```





### 1.12插入线程(插队线程)

#### 是什么：

在一个线程A的运行过程中插入一个线程B让它插队运行。

#### 为什么：

##### （1）为什么要使用插入线程？

1. 实现线程的依赖性调度

在多线程程序中，某些线程可能依赖于其他线程的执行结果。如果依赖线程不能及时完成，就会影响整个程序的运行。通过插入线程，可以确保依赖线程优先运行，从而加速整个任务的执行。

- 主线程需要等待一个初始化线程完成数据库连接。

- 数据处理线程需要优先获取输入数据。

```java
Thread dataLoader = new Thread(() -> {
    System.out.println("Loading data...");
    // 模拟数据加载
    try {
        Thread.sleep(2000);
    } catch (InterruptedException e) {
        e.printStackTrace();
    }
    System.out.println("Data loaded.");
});


Thread mainTask = new Thread(() -> {
    try {
        dataLoader.join(); // 插入线程，等待数据加载完成
    } catch (InterruptedException e) {
        e.printStackTrace();
    }
    System.out.println("Processing data...");
});


dataLoader.start();
mainTask.start();
```

**输出：**

```java
Loading data...
Data loaded.
Processing data...
```

#### 怎么办：

##### （1）如何实现插入线程？

- 使用 join() 方法
  - `join()` 方法可以让一个线程在执行过程中“插入”到当前线程的执行队列中，强制当前线程等待这个插入线程执行完成后再继续运行。

```java
public class JoinExample {
    public static void main(String[] args) {
        Thread insertThread = new Thread(() -> {
            for (int i = 0; i < 5; i++) {
                System.out.println("Insert thread running: " + i);
                try {
                    Thread.sleep(500); // 模拟任务
                } catch (InterruptedException e) {
                    e.printStackTrace();
                }
            }
        });

        
        Thread mainThread = new Thread(() -> {
            System.out.println("Main thread waiting for insert thread.");
            try {
                insertThread.join(); // 等待插入线程执行完成
            } catch (InterruptedException e) {
                e.printStackTrace();
            }
            System.out.println("Main thread resumes after insert thread.");
        });

        
        insertThread.start();
        mainThread.start();
    }
}
```

```java

Insert thread running: 1
Insert thread running: 2
Insert thread running: 3
Insert thread running: 4
Main thread resumes after insert thread.
```





## 2.线程同步

### 是什么：

**线程同步**是指==多个线程==在访问==共享资源==时通过某种方式保证在==某一个时间段内只有一个线程能够访问==资源，从而避免出现数据不一致的问题。

### 为什么：

#### （1）为什么要使用线程同步？

在并发程序中，多个线程可能同时访问和修改同一共享资源。如果没有适当的控制和同步，可能会发生以下问题：

1. **数据竞争（Race Condition）**：
   - 如果两个线程同时访问共享资源并且至少有一个线程对该资源进行修改，就会发生数据竞争。不同的线程可能会对同一数据执行操作，最终导致数据不一致或错误的结果。
2. **不可预测的行为**：
   - 多线程操作的顺序不可预测。如果多个线程同时修改同一个数据，而没有同步机制来控制它们的执行顺序，程序的行为会变得不可预测，导致错误或程序崩溃。
3. **死锁（Deadlock）**：
   - 如果多个线程相互依赖，并且在没有适当的锁机制下互相等待释放资源，就可能会导致线程无法继续执行，从而造成死锁。

==多线程环境下不使用线程同步会导致的问题示例：==

如果不使用线程同步（即不加 `synchronized` 关键字），会发生**数据竞争（Race Condition）**，因为多个线程在没有同步机制的保护下同时修改 `count` 变量。由于多个线程可能会在相同的时间访问 `count`，会出现并发问题，导致最终的结果不正确。

- 线程1和线程2都试图对 `count` 进行增加（`count++`）。

- `count++` 其实是由三个步骤组成的：

  1. 读取 `count` 的值。
  2. 在当前值基础上加1。
  3. 将结果写回 `count`。

  这里==正确的操作应该是线程1顺序执行完上述三个步骤接着轮到线程2顺序执行完上述三个步骤，接着轮到线程3==，，，但是==因为这里是并发的多线程环境所以可能线程1的三个步骤还没有执行完此时时间片用完就轮到线程2执行了==，这就会导致一个问题：比如说线程1在执行步骤1的时候读取到count=1000，接着线程1继续执行步骤2，执行完步骤2还没有执行步骤3的时候，此时轮到线程2执行，线程2在执行步骤1的时候读取到count=1000（因为此时线程1修改过后的count值还没有写回count，所以线程2读取到的count值还是旧的值），接着线程2再执行步骤2和步骤3最终count=1001，即使这时候又轮到线程1执行了它也是将自己计算得到的count=1001写回去了，所以说有一些操作被覆盖住了。

**没有同步的代码：**

```java
class Counter {
    private int count = 0;

    // 不使用同步，多个线程会同时访问和修改 count
    public void increment() {
        count++;
    }

    public int getCount() {
        return count;
    }
}



public class SynchronizationExample {
    public static void main(String[] args) throws InterruptedException {
        Counter counter = new Counter();

        // 创建两个线程并启动
        Thread t1 = new Thread(() -> {
            for (int i = 0; i < 1000; i++) {
                counter.increment();
            }
        });

        Thread t2 = new Thread(() -> {
            for (int i = 0; i < 1000; i++) {
                counter.increment();
            }
        });

        t1.start();
        t2.start();

        // 等待两个线程完成
        t1.join();
        t2.join();

        System.out.println("Final count: " + counter.getCount());//最后可能的输出为1800或其他任何小于2000的值
    }
}
```

1. **数据竞争**：线程1和线程2都尝试同时增加 `count`，并且这两个操作没有同步控制，导致它们互相干扰。
2. **线程调度不可预测**：在并发环境中，线程的执行顺序由操作系统的线程调度器决定，这个顺序是不可预测的。如果两个线程的操作交错执行，可能会导致它们读取相同的 `count` 值，并将增量结果写回，导致丢失一些增量。
3. **丢失更新**：假设线程1读取了 `count` 的值为1000，线程2也读取了相同的值1000。然后线程1和线程2分别加1，将结果写回，但由于两个线程在写回的时机重叠，最后 `count` 只增加1而不是2。

### 怎么办：

#### （1）如何实现线程同步呢？

Java 提供了几种线程同步的方法，主要通过锁机制来保证同一时刻只有一个线程能够访问共享资源。常见的锁机制有：

##### ①`synchronized` 锁

`synchronized` 是 Java 中最常用的锁，它可以用来修饰方法或代码块，确保在同一时刻只有一个线程能执行该方法或代码块。

- **同步动态方法**：锁住当前对象实例（`this`），在方法内部执行对共享数据的操作。
- **同步静态方法**：锁住当前类的 Class 对象，在方法内部执行对共享数据的操作。
- **同步代码块**：锁住指定对象（对象必须是唯一的，否则就起不到锁的作用），在代码块内部执行对共享数据的操作。

**示例代码：**

###### 1.同步动态方法

```java
class Counter {
    private int count = 0;

    // 同步方法，保证每次只有一个线程访问
    public synchronized void increment() {
        count++;
    }

    public int getCount() {
        return count;
    }
}



public class SynchronizationExample {
    public static void main(String[] args) throws InterruptedException {
        Counter counter = new Counter();

        // 创建两个线程并启动
        Thread t1 = new Thread(() -> {
            for (int i = 0; i < 1000; i++) {
                counter.increment();
            }
        });

        Thread t2 = new Thread(() -> {
            for (int i = 0; i < 1000; i++) {
                counter.increment();
            }
        });

        t1.start();
        t2.start();

        // 等待两个线程完成
        t1.join();
        t2.join();

        System.out.println("Final count: " + counter.getCount());//最后结果2000
    }
```

##### ②`ReentrantLock` 锁

`ReentrantLock` 是 `java.util.concurrent.locks` 包中的一个类，提供了比 `synchronized` 更加灵活的锁机制。例如，`ReentrantLock` 允许尝试获取锁、定时获取锁、锁的公平性等特性。

**示例代码：**

```java
import java.util.concurrent.locks.Lock;
import java.util.concurrent.locks.ReentrantLock;

class Counter {
    private int count = 0;
    private Lock lock = new ReentrantLock();

    // 使用 ReentrantLock 来实现同步
    public void increment() {
        lock.lock();  // 加锁
        try {
            count++;
        } finally {
            lock.unlock();  // 确保解锁
        }
    }

    public int getCount() {
        return count;
    }
}




public class LockExample {
    public static void main(String[] args) throws InterruptedException {
        Counter counter = new Counter();

        // 创建两个线程并启动
        Thread t1 = new Thread(() -> {
            for (int i = 0; i < 1000; i++) {
                counter.increment();
            }
        });

        Thread t2 = new Thread(() -> {
            for (int i = 0; i < 1000; i++) {
                counter.increment();
            }
        });

        t1.start();
        t2.start();

        // 等待两个线程完成
        t1.join();
        t2.join();

        System.out.println("Final count: " + counter.getCount());//最后结果2000
    }
}
```

在这个示例中，`ReentrantLock` 被用于控制对 `count` 变量的访问。在访问共享资源时，线程会先获取锁，确保同一时刻只有一个线程访问资源，操作完成后释放锁。

### 2.3同步代码块解决数据安全问题【应用】

- 安全问题出现的条件

  - 是多线程环境

  - 有共享数据

  - 有多条语句操作共享数据

- 如何解决多线程安全问题呢?

  - 基本思想：让程序没有安全问题的环境

- 怎么实现呢?

  - 把多条语句操作共享数据的代码给锁起来，让任意时刻只能有一个线程执行即可

  - Java提供了同步代码块的方式来解决

- 同步代码块格式：

  ```java
  synchronized(任意对象) { 
  	多条语句操作共享数据的代码 
  }
  ```

  synchronized(任意对象)：就相当于给代码加锁了，任意对象就可以看成是一把锁

- 同步的好处和弊端  

  - 好处：解决了多线程的数据安全问题

  - 弊端：当线程很多时，因为每个线程都会去判断同步上的锁，这是很耗费资源的，无形中会降低程序的运行效率

- 代码演示

  ```java
  public class SellTicket implements Runnable {
      private int tickets = 100;
      private Object obj = new Object();
  
      @Override
      public void run() {
          /*
          这里有一个问题，那就是多线程可以在这里while(true)循环中实现切换吗，它不会由一个线程一直把票卖光吧？
          可以实现。
          1、首先这里我们定义了循环，这就可以保证一直卖票直到将票卖完。
          2、接着我们定义了同步代码块，这就可以保证共享数据的安全性，也就是在任意时刻只有一个线程可以访问共享数据。
          3、当一个线程进入循环以后首先会进入同步代码块确保只有当前线程可以操纵共享数据，接着会去判断票是否卖完，
          	卖完了就结束循环，没卖完就继续卖；结束一轮循环后已经走出同步代码块，这时候还没有走出循环，所以会
          	去看当前时间片在哪里，如果还在当前线程这里则当前线程继续执行循环，如果在别的线程那里则让别的线程执行
          	操作，等到当前线程重新取得时间片之后当前线程继续执行循环。
          */
          while (true) {
              synchronized (obj) { // 对可能有安全问题的代码加锁,多个线程必须使用同一把锁
                  //t1进来后，就会把这段代码给锁起来
                  if (tickets > 0) {
                      try {
                          Thread.sleep(100);
                          //t1休息100毫秒
                      } catch (InterruptedException e) {
                          e.printStackTrace();
                      }
                      //窗口1正在出售第100张票
                      System.out.println(Thread.currentThread().getName() + "正在出售第" + tickets + "张票");
                      tickets--; //tickets = 99;
                  } else {
                      break;
                  }
              }
              //t1出来了，这段代码的锁就被释放了
          }
      }
  }

      public static void main(String[] args) {
          SellTicket st = new SellTicket();

          Thread t2 = new Thread(st, "窗口2");
          Thread t3 = new Thread(st, "窗口3");
  ```

## 3.生产者消费者

### 3.1生产者和消费者模式概述【应用】

#### 是什么：

生产者消费者模式是一个十分经典的多线程协作的模式。

所谓生产者消费者问题，实际上主要是包含了两类线程：

- 一类是生产者线程用于生产数据
- 一类是消费者线程用于消费数据

为了解耦生产者和消费者的关系，通常会采用共享的数据区域，就像是一个仓库

生产者生产数据之后直接放置在共享数据区中，并不需要关心消费者的行为

消费者只需要从共享数据区中去获取数据，并不需要关心生产者的行为

#### 为什么：

##### （1）为什么要使用生产者消费者模式？

根据实际的业务场景创建的生产者消费者模式，在实际的业务中比如消息队列中就需要生产者生产消息、消费者消费消息。

#### 怎么办：

##### （1）如何实现生产者消费者模式？

- 使用Object类中的 `wait()` 和 `notify()` 方法实现生产者消费者模式，`wait()` 和 `notify()` 是 Java 中用于定义线程间顺序关系的方法

**代码示例：**

```java
class SharedBuffer {
    private int item;
    private boolean isEmpty = true;

    // 生产者放入数据
    public synchronized void produce(int item) throws InterruptedException {
        while (!isEmpty) {
            wait();  // 如果缓冲区不为空，则等待消费者消费
        }
        this.item = item;
        System.out.println("生产者生产了: " + item);
        isEmpty = false;
        notify();  // 通知消费者可以消费
    }

    // 消费者获取数据
    public synchronized int consume() throws InterruptedException {
        while (isEmpty) {
            wait();  // 如果缓冲区为空，则等待生产者生产
        }
        System.out.println("消费者消费了: " + item);
        isEmpty = true;
        notify();  // 通知生产者可以生产
        return item;
    }
}



class Producer implements Runnable {
    private SharedBuffer buffer;

    public Producer(SharedBuffer buffer) {
        this.buffer = buffer;
    }

    @Override
    public void run() {
        try {
            for (int i = 0; i < 10; i++) {
                buffer.produce(i);
                Thread.sleep(500);  // 模拟生产耗时
            }
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
    }
}



class Consumer implements Runnable {
    private SharedBuffer buffer;

    public Consumer(SharedBuffer buffer) {
        this.buffer = buffer;
    }

    @Override
    public void run() {
        try {
            for (int i = 0; i < 10; i++) {
                buffer.consume();
                Thread.sleep(1000);  // 模拟消费耗时
            }
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
    }
}




public class ProducerConsumerDemo {
    public static void main(String[] args) {
        SharedBuffer buffer = new SharedBuffer();

        // 创建生产者和消费者线程
        Thread producer = new Thread(new Producer(buffer));
        Thread consumer = new Thread(new Consumer(buffer));

        // 启动线程
        producer.start();
        consumer.start();
    }
}
```

##### （2）wait方法和sleep方法有什么异同？

==相同点：==

- **暂停线程执行：** `wait()` 和 `sleep()` 都可以让线程暂停执行一定时间，导致线程进入“非活动”状态，暂时不参与 CPU 调度。

==不同点：==

| 特性         | `wait()`                                                     | `sleep()`                                                |
| ------------ | ------------------------------------------------------------ | -------------------------------------------------------- |
| **类**       | 属于 `Object` 类的方法，因此可以调用任意对象上的 `wait()`。  | 属于 `Thread` 类的方法，直接调用线程对象上的 `sleep()`。 |
| **调用方式** | 必须在同步代码块或同步方法中调用（持有锁的情况下）。         | 可以在任何地方调用，不需要获取锁。                       |
| **锁释放**   | 在调用 `wait()` 后，==当前线程释放锁，其他线程可以获取锁==。 | 调用 `sleep()` 后，==线程仍持有锁，不会释放锁==。        |
| **阻塞类型** | 线程进入等待状态，直到其他线程调用该对象的 `notify()` 或 `notifyAll()`才能唤醒线程。 | 线程进入休眠状态，直到指定的时间过去。                   |
| **参数**     | 没有指定时间时，线程会一直等待直到被 `notify()` 唤醒；也可以指定超时时间。 | 需要指定一个时间（毫秒）来表示线程休眠的时间。           |
| **用途**     | 用于规定线程之间的执行顺序。                                 | 用于线程的延时执行，或者简单的暂停操作。                 |
| **异常**     | `wait()` 会抛出 `InterruptedException` 异常。                | `sleep()` 会抛出 `InterruptedException` 异常。           |



###### notes：这里提到的当一个线程通过调用wait()方法进入等待状态后，必须等到其他线程调用该对象的notify()方法来唤醒该线程，如何理解这里的对象是什么？

在 Java 中，`wait()`、`notify()` 和 `notifyAll()` 方法都定义在 `Object` 类中。即每个`Object`对象都有一个隐式的监视器锁（monitor lock），`wait()`、`notify()` 和 `notifyAll()` 方法是通过该锁对象来进行线程间的通信的。

- **`wait()`**：调用该方法的线程会进入等待状态，直到 **另一个线程调用同一对象的 `notify()` 或 `notifyAll()` 方法**才能唤醒当前线程（由此可以证明调用wait()方法后当前线程会释放锁，否则别的线程就没法再去获取锁从而调用同一对象的notify()方法了）。
- **`notify()`**：会随机唤醒一个正在等待该对象监视器锁的线程，唤醒后，线程会尝试重新获得锁，继续执行。
- **`notifyAll()`**：会唤醒所有正在等待该对象监视器锁的线程，唤醒后，线程们会尝试重新获得锁，继续执行。

```java
class ProducerConsumer {
    private int product = 0;
    private final Object lock = new Object();  // 锁对象

    // 生产者方法
    public void produce() throws InterruptedException {
        synchronized (lock) {  // 获取锁
            while (product >= 1) {
                lock.wait();  // 如果产品已满，生产者等待
            }
            product++;  // 生产一个产品
            System.out.println("生产者生产了产品，产品数量：" + product);
            lock.notifyAll();  // 通知消费者消费
        }
    }

    // 消费者方法
    public void consume() throws InterruptedException {
        synchronized (lock) {  // 获取锁
            while (product <= 0) {
                lock.wait();  // 如果没有产品，消费者等待
            }
            product--;  // 消费一个产品
            System.out.println("消费者消费了产品，产品数量：" + product);
            lock.notifyAll();  // 通知生产者生产
        }
    }
}
```



###### notes：`wait()`方法和`notify()`方法的调用对象可以是隐式不加声明的。

就比如说上述生产者消费者模式的实例代码中就没有声明`wait()`方法和`notify()`方法的调用对象，这是因为它们隐式地调用了同步代码块`synchronized` 所属的对象。

```java
class SharedBuffer {
    private int item;
    private boolean isEmpty = true;

    // 生产者放入数据
    public synchronized void produce(int item) throws InterruptedException {
        while (!isEmpty) {
            wait();  // 这里省略了当前wait()方法的调用对象，即当前同步代码块的对象：SharedBuffer对象
        }
        this.item = item;
        System.out.println("生产者生产了: " + item);
        isEmpty = false;
        notify();  // 通知消费者可以消费
    }

    // 消费者获取数据
    public synchronized int consume() throws InterruptedException {
        while (isEmpty) {
            wait();  // 如果缓冲区为空，则等待生产者生产
        }
        System.out.println("消费者消费了: " + item);
        isEmpty = true;
        notify();  // 通知生产者可以生产
        return item;
    }
}
```



##### （3）生产者消费者模式和前面提到的线程同步有什么异同？

==相同点：==

- 线程同步和生产者消费者模式都涉及 **多个线程对共享资源的访问**，并且需要某种方式来 **协调线程间的行为**，确保程序的正确性。
  - 线程同步涉及对共享资源的访问这点没问题。
  - 生产者消费者模式中涉及对共享资源的访问该如何理解？在生产者消费者模式中也是通过在同步代码块中通过对于共享资源的判断从而调用`wait()`方法和`notify()`方法实现的。

==不同点：==

- 线程同步：在多线程模式下访问共享资源时，确保一个时间段内只有一个线程可以访问该资源，通过`synchronized`锁确定的是共享资源的访问问题

- 生产者消费者模式：通过`wait()`方法和`notify()`方法确定的是多个线程之间的执行顺序问题





- Object类的等待和唤醒方法

  | 方法名              | 说明                                       |
  | ---------------- | ---------------------------------------- |
  | void wait()      | 导致当前线程等待，直到另一个线程调用该对象的 notify()方法或 notifyAll()方法 |
  | void notify()    | 唤醒正在等待对象监视器的单个线程                         |
  | void notifyAll() | 唤醒正在等待对象监视器的所有线程                         |





### 3.2生产者和消费者案例【应用】

下述定义了一个生产者消费者模型，生产者（`Cooker`）和消费者（`Foodie`）通过互相协作来生产和消费包子。生产者负责生产包子，而消费者负责吃包子。为了避免程序进入无限循环，我们需要为程序设置明确的退出条件。否则，生产者和消费者可能会一直运行下去，导致程序无法停止。

- 生产者-消费者模型的基本流程

1. **生产者**：
   - 生产者检查桌子上是否有包子，如果没有包子，生产者就会生产包子。
   - 生产完包子后，生产者会通知消费者，唤醒等待的消费者。
   - 如果桌子上已经有包子，生产者就会等待消费者吃掉包子后再继续生产。
2. **消费者**：
   - 消费者检查桌子上是否有包子，如果有包子，消费者就会吃掉包子。
   - 吃完包子后，消费者会通知生产者生产更多包子。
   - 如果桌子上没有包子，消费者就会等待生产者生产包子。

#### notes：设置退出条件

如果这里的条件仅仅是：当桌子上没有包子的时候生产者生产包子，当桌子上有包子的时候消费者消费包子，则这个生产者消费者模式永远不会退出（因为桌子上包子的状态要么就是有要么就是没有，不管是哪一种状态总有一个线程正在运行，所以这个模式永远不会停止），所以我们需要额外设置一个退出条件，当满足条件的时候程序自动退出，我们可以设置一个变量`Desk.count = 10` 是一个退出条件，它表示消费者最多只能吃10个包子，每当消费者线程执行一次则执行一次`count--`操作表示消费者吃了一个包子。一旦消费者吃完10个包子，整个生产者消费者模式就会停止。



- 案例需求

  + 桌子类(Desk)：定义锁对象变量,定义标记桌子上有无包子的变量，还得定义消费者当前还能吃几个包子的变量（用于控制程序退出）

  + 生产者类(Cooker)：实现Runnable接口，重写run()方法，设置生产者线程要执行的动作

      1.判断是否有包子,决定当前线程是否执行

      2.如果有包子,就进入等待状态,如果没有包子,继续执行,生产包子

      3.生产包子之后,更新桌子上包子状态,唤醒消费者消费包子

  + 消费者类(Foodie)：实现Runnable接口，重写run()方法，设置消费者线程要执行的动作

      1.判断是否有包子,决定当前线程是否执行

      2.如果没有包子,就进入等待状态,如果有包子,就消费包子

      3.消费包子后,更新桌子上包子状态,唤醒生产者生产包子

  + 测试类(Demo)：里面有main方法，main方法中的代码步骤如下

      创建生产者线程和消费者线程对象

      分别开启两个线程

- 代码实现

  ```java
  public class Desk {
      // 标记桌子上是否有包子
      //true 就表示桌子上有包子的,此时允许消费者执行
      //false 就表示桌子上没有包子的,此时允许生产者执行
      public static boolean flag = false;
  
      // 表示消费者还能吃几个包子，初始值为 10，消费者线程每运行一次执行一次count--操作，
      // 当count==0 时设置程序退出，避免无限循环（用于控制程序退出的变量）
      public static int count = 10;
  
      // 这是一个用于同步的锁对象，所有线程（生产者和消费者）都需要用它来保证对共享资源（桌子上包子）的互斥访问。
      public static final Object lock = new Object();
  }
  
  
  public class Cooker extends Thread {
      /**
      生产者要执行的操作：
      1，判断桌子上是否有包子
      	如果有就等待，
      	如果没有才生产。
      2，将生产的包子放在桌子上（设置桌子上包子的状态为有）。
      3，叫醒等待的消费者开吃。
      */
      @Override
      public void run() {
          while (true) {  // 生产者进入循环，持续生产包子
              synchronized (Desk.lock) {  // 获取锁，保证对桌子资源的同步访问
                  if (Desk.count == 0) {  
                      // 如果消费者一个包子都吃不了了（表明消费者已经吃了10个包子了），则退出循环
                      break;
                  } else {
                      if (!Desk.flag) {  // 如果桌子上没有包子
                          System.out.println("厨师正在生产汉堡包");  // 生产包子的提示
                          Desk.flag = true;  // 设置桌子上有包子
                          Desk.lock.notifyAll();  // 唤醒等待的消费者（吃货）
                      } else {
                          try {
                              Desk.lock.wait();  // 如果桌子上有包子，生产者等待
                          } catch (InterruptedException e) {
                              e.printStackTrace();
                          }
                      }
                  }
              }
          }
      }
  }
  
  
  
  public class Foodie extends Thread {
      /**
      消费者要执行的操作：
      1，判断桌子上是否有包子
      	如果没有就等待，
      	如果有才消费。
      2，将桌子上的包子吃掉（设置桌子上包子的状态为无），同时别忘了执行count--操作表明
         消费者还能再吃的包子数量减1，这个操作是为了避免无限循环。
      3，叫醒等待的生产者继续生产。
      */
      @Override
      public void run() {
          while (true) {  // 消费者进入循环，持续消费包子
              synchronized (Desk.lock) {  // 获取锁，保证对桌子资源的同步访问
                  if (Desk.count == 0) {  
                      // 如果消费者一个包子都吃不了了（表明消费者已经吃了10个包子了），则退出循环
                      break;
                  } else {
                      if (Desk.flag) {  // 如果桌子上有包子
                          System.out.println("吃货在吃汉堡包");  // 吃包子的提示
                          Desk.flag = false;  // 设置桌子上没有包子
                          Desk.lock.notifyAll();  // 唤醒生产者继续生产
                          Desk.count--;  // 消费者还能吃的包子数量减一
                      } else {
                          try {
                              Desk.lock.wait();  // 如果桌子上没有包子，消费者等待
                          } catch (InterruptedException e) {
                              e.printStackTrace();
                          }
                      }
                  }
              }
          }
      }
  }
  
  
  
  public class Demo {
      public static void main(String[] args) {
          Foodie f = new Foodie();
          Cooker c = new Cooker();
  
          f.start();
          c.start();
      }
  }
  ```

### 3.4阻塞队列基本使用【理解】

#### 是什么：

**阻塞队列（Blocking Queue）** 是一种线程安全的数据结构，支持多线程场景下的生产者-消费者模型。它的核心特点是：

- **线程安全性**：在多线程环境下，不需要显式地进行同步操作。
- **阻塞特性**：当队列为空或满时，操作会阻塞直到队列状态允许操作。

#### 为什么：

##### （1）为什么要使用阻塞队列来实现生产者消费者模型？

1. 简化线程之间执行顺序的操作

阻塞队列内置了线程同步机制，自动处理生产者和消费者之间的执行顺序，避免手动编写复杂的 `wait()` 和 `notify()`代码（其实阻塞队列底层代码中依然用的是`wait()`方法，但是这个过程是封装好的不需要我们编辑的）。

- 传统同步的复杂性，如果没有阻塞队列，生产者和消费者之间的同步需要显式使用锁和条件变量，增加了代码复杂性：

```java
synchronized (lock) {
    while (队列满) {
        lock.wait(); // 显式等待
    }
    // 插入元素
    lock.notifyAll(); // 显式通知消费者
}
```

- 阻塞队列的简化，阻塞队列通过内置的方法（如 `put()` 和 `take()`）自动管理同步逻辑，开发者无需关心线程间的锁竞争。

```Java
queue.put(item); // 自动阻塞直到有空间
queue.take();    // 自动阻塞直到有元素
```



2. 简化线程安全的操作

阻塞队列在设计时就考虑到了线程安全，能够在多线程环境下正确处理并发操作。

```java
BlockingQueue<Integer> queue = new ArrayBlockingQueue<>(10);

Thread producer = new Thread(() -> {
    try {
        for (int i = 0; i < 10; i++) {
            queue.put(i); // 自动处理线程安全和阻塞
        }
    } catch (InterruptedException e) {
        e.printStackTrace();
    }
});



Thread consumer = new Thread(() -> {
    try {
        while (true) {
            Integer item = queue.take(); // 自动处理线程安全和阻塞
        }
    } catch (InterruptedException e) {
        e.printStackTrace();
    }
});
```
