## 1. 线程池

### 1.1 线程状态介绍

当线程被创建并启动以后，它既不是一启动就进入了执行状态，也不是一直处于执行状态。线程对象在不同的时期有不同的状态。那么Java中的线程存在哪几种状态呢？Java中的线程状态被定义在了`java.lang.Thread.State`枚举类中，`State`枚举类的源码如下：

```java
public class Thread {
    
    public enum State {
    
        /* 创建态 */
        NEW , 

        /* 就绪态 */
        RUNNABLE , 

        /* 阻塞态 */
        BLOCKED , 

        /* 等待态 */
        WAITING , 

        /* 计时等待态 */
        TIMED_WAITING , 

        /* 终止态 */
        TERMINATED;
    
	}
    
    // 获取当前线程的状态
    public State getState() {
        return jdk.internal.misc.VM.toThreadState(threadStatus);
    }
    
}
```

通过源码我们可以看到Java中的线程存在6种状态，每种线程状态的含义如下

| 线程状态      | 具体含义                                                     |
| ------------- | ------------------------------------------------------------ |
| NEW           | 一个尚未启动的线程的状态。也称之为初始状态、开始状态。线程刚被创建，但是并未启动。==还没调用start方法。MyThread t = new MyThread()只有线程象，没有线程特征==。 |
| RUNNABLE      | 当我们==调用线程对象的start方法，那么此时线程对象进入了RUNNABLE状态==。那么此时才是真正的在JVM进程中创建了一个线程，线程一经启动并不是立即得到执行，线程的运行与否要听令于CPU的调度。==万事俱备只欠CPU==。 |
| BLOCKED       | 当一个线程试图获取一个对象锁，而该对象锁被其他的线程持有，则该线程进入Blocked状态；当该线程持有锁时，该线程将变成Runnable状态。==除了CPU还缺其他资源==。 |
| WAITING       | 一个正在等待的线程的状态。也称之为等待状态。==造成线程等待的原因有两种，分别是调用Object.wait()、join()方法==。处于等待状态的线程，正在等待其他线程去执行一个特定的操作。例如：因为wait()而等待的线程正在等待另一个线程去调用notify()或notifyAll()；一个因为join()而等待的线程正在等待另一个线程结束。 |
| TIMED_WAITING | 一个在限定时间内等待的线程的状态。也称之为限时等待状态。==造成线程计时等待状态的原因是：Thread.sleep(long)==。 |
| TERMINATED    | 一个完全运行完成的线程的状态。也称之为终止状态、结束状态     |

### 1.2 线程池-基本原理

#### 是什么：

线程池（Thread Pool）是一种预先创建一组线程并将其维护在池中的机制。当任务需要执行时，线程池从池中分配一个空闲的线程来执行任务，执行完毕后，线程会返回池中等待下一个任务。这样避免了频繁创建和销毁线程的开销，提升了系统的性能和响应速度。	

#### 为什么：

##### （1）为什么要使用线程池？

1. **减少线程创建和销毁的开销**

   - **创建线程的代价高**：每次创建一个新的线程需要操作系统分配资源，进行上下文切换、内存分配等，这些操作开销较大。如果每次任务都创建和销毁线程，系统的性能会显著下降。

   - **线程池复用**：线程池会预先创建一定数量的线程并重复利用，避免了每次任务都创建新线程，极大地减少了线程创建和销毁的开销。

2. **提高性能**

   - **任务调度优化**：线程池通过合理调度线程来执行任务，避免了因频繁创建和销毁线程而带来的资源浪费。它可以有效地提高任务的处理效率，减少延迟。

   - **线程复用**：在任务执行完成后，线程池中的线程会返回池中而不是销毁，等待下一个任务的到来。这意味着线程池可以最大化线程的使用效率，从而提升性能。

3. **限制并发线程数量，避免资源耗尽**

   - **控制并发量**：如果系统中并发线程过多，可能会导致系统资源（如内存、CPU）被过度占用，甚至引发系统崩溃。线程池可以限制同时运行的线程数，确保线程数量不会超过系统资源的承载能力。

   - **避免资源竞争**：线程池能够控制同时并发的任务数，防止因过多的线程争夺CPU、内存等资源而导致的性能下降和系统负载过高。

4. **简化线程管理**

   - **自动管理线程生命周期**：线程池自动管理线程的创建、销毁、调度和回收，开发者无需手动创建和销毁线程，减少了程序的复杂度和出错的可能。

   - **任务排队与优先级处理**：线程池通常会使用任务队列来存储待执行的任务，确保任务按顺序或优先级执行，避免任务丢失或错乱。

#### 怎么办：

##### （1）如何使用线程池？

1. **创建线程池**

**`Executors`** 是线程池的工厂类，用来创建各种类型的线程池对象。

**`ExecutorService`** 是线程池的接口类（泛指各种类型的线程池对象），用来管理线程池对象，提供 `submit` 和 `shutdown`方法。

常见的线程池对象如下：

- **固定大小线程池**：适用于需要处理固定数量的并发任务的场景，在创建的时候需要指定线程池的大小。

- **可动态扩容的线程池**：适用于任务量不确定、线程可以动态创建和销毁的场景，在创建的时候不需要指定线程池的大小。

```java
// 创建一个固定大小为 4 的线程池
ExecutorService threadPool = Executors.newFixedThreadPool(4);

// 创建一个可扩容的线程池
ExecutorService threadPool = Executors.newCachedThreadPool();
```



2. **提交任务给线程池**

使用线程池时，通常会提交任务让线程池中的线程来执行。可以使用以下两种方式提交任务：

- 方式1：提交 `Runnable` 接口的任务

​	`Runnable` 接口表示一个无返回值的任务，使用 `submit()` 或 `execute()` 提交。

```java
// 创建一个可缓存的线程池
ExecutorService threadPool = Executors.newCachedThreadPool();

// 创建一个Runnable任务
Runnable task = new Runnable() {
    @Override
    public void run() {
        System.out.println(Thread.currentThread().getName() + " is executing the task.");
    }
};

// 提交任务给线程池
threadPool.submit(task);
```

- 方式2：提交`Callable` 接口的任务

​	`Callable` 接口与 `Runnable` 类似，但它可以返回一个结果，可以通过 `Future` 对象获取任务执行结果。

```Java
// 创建一个可缓存的线程池
ExecutorService threadPool = Executors.newCachedThreadPool();

// 创建一个Callable任务
Callable<Integer> task = new Callable<Integer>() {
    @Override
    public Integer call() throws Exception {
        System.out.println(Thread.currentThread().getName() + " is executing the task.");
        return 123;
    }
};

// 提交任务给线程池
Future<Integer> future = threadPool.submit(task);

// 获取任务执行的结果
try {
    Integer result = future.get();  // 阻塞等待任务完成
    System.out.println("Task result: " + result);
} catch (Exception e) {
    e.printStackTrace();
}
```

##### notes：注意当线程池对象用submit()方法提交线程任务时如果有返回值的话统一用Future类对象去接收返回结果



##### notes：注意区分这里的Future类对象和之前创建多线程时用到的FutureTask类对象

二者的作用介绍如下：

- Future对象：用于接收线程池提交线程任务后的返回结果

- `FutureTask`对象：在多线程创建方式中有一种是实现`Callable`接口，在那里我们要做的是首先实现`Callable`接口，接着利用`FutureTask`类对象包装`Callable`接口的实现类，最后将`FutureTask`对象放入`Thread`的构造器中，因为`Thread`的构造器只接受`Runnable`接口的实现类对象而`FutureTask`对象实现了`Runnable`接口





3. **关闭线程池**

线程池执行完任务后，应该关闭，以释放资源。可以使用 `shutdown()` 方法来关闭线程池。

- `shutdown()`：平滑关闭，允许已提交的任务执行完成，但不再接受新任务。

```java
// 等待任务执行完成并关闭线程池
threadPool.shutdown();
```





### 1.3 可扩容线程池的用法

**使用Executors中所提供的静态方法来创建线程池**

​	static ExecutorService newCachedThreadPool() : 创建一个可以扩容的线程池

**本线程池的特点：**

- 线程池的初始大小为 0。
- 如果有新的任务提交：
  - 如果没有空闲线程，则创建新线程。
  - 如果有空闲线程，则复用空闲线程。
- 如果线程空闲超过 60 秒，就会被回收（该线程会被销毁，释放资源）。

- 线程池的初始大小为 0，线程池刚创建的时候里面一个线程也没有（不管是核心线程还是非核心线程都没有），后续提交任务的时候才创建线程。

**代码实现 :** 

```java
package com.itheima.mythreadpool;

import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;

public class MyThreadPoolDemo {
    public static void main(String[] args) throws InterruptedException {

        //1,创建一个默认的线程池对象.池子中默认是空的.默认最多可以容纳int类型的最大值.
        /*
        Executors --- 线程池的工厂类（可以创建各种类型的线程池）
        ExecutorService --- 线程池的接口，用来管理线程池对象
        */
        ExecutorService executorService = Executors.newCachedThreadPool();
                
        /*
        下述代码的含义：
        创建Runnable接口的匿名实现类，重写run()方法
        executorService.submit(new Runnable() {
            @Override
            public void run() {
                System.out.println(Thread.currentThread().getName() + "在执行了");
            }
        });
        */
        executorService.submit(()->{
            System.out.println(Thread.currentThread().getName() + "在执行了");
        });

        
        /*
        这里为什么要调用Thread.sleep()方法？
        对线程复用的影响：
        如果没有 Thread.sleep：
        	第一个任务执行完成后，线程池中的线程可能立即进入空闲状态，然后迅速复用这个线程来执行第二个任务。
        如果有 Thread.sleep：
            延迟提交第二个任务，可能导致：
            第一个任务完成后，线程空闲超过线程池的回收时间（如 newCachedThreadPool 默认是 60 秒），线程可能被回收。
            第二个任务被提交时，线程池需要重新创建线程来执行任务。
        */
        Thread.sleep(2000);

        executorService.submit(()->{
            System.out.println(Thread.currentThread().getName() + "在执行了");
        });

        executorService.shutdown();
    }
}
```





### 1.4 固定大小线程池的用法

**使用Executors中所提供的静态方法来创建线程池**

​	static ExecutorService newFixedThreadPool(int nThreads) : 创建一个指定最多线程数量的线程池

**本线程池的特点：**

- 线程池的大小是固定的，最多可以容纳 `nThreads` 个线程。
- 线程池的初始大小为 0。
- 如果有新的任务提交：
  - 如果没有空闲线程且线程池中仍未达到最大线程数，则会创建新的线程来执行任务。
  - 如果有空闲线程，则复用空闲线程来执行任务。
  - 如果线程池中的线程数已经达到最大线程数（`nThreads`），且等待队列未满，则新提交的任务会被放入等待队列，等待空闲线程来执行。
  - 如果线程池中的线程数已经达到最大线程数，且队列已满，则会根据设置的 **拒绝策略** 来处理新任务。默认拒绝策略为 `AbortPolicy`，即抛出 `RejectedExecutionException` 异常。

**代码实现 :** 

```java
package com.itheima.mythreadpool;

import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;
import java.util.concurrent.ThreadPoolExecutor;

public class MyThreadPoolDemo2 {
    public static void main(String[] args) {
        /*
        newFixedThreadPool(10)：
        创建一个线程池，最多包含 10 个线程。
        线程池中的线程是固定的，不会动态扩展或回收。
        当有任务提交时，如果线程池中的线程不足，新任务将进入等待队列。
        */
        //这里的参数10指的是最多容纳10个线程而不是线程池中一开始就有10个线程，
        //一开始的话线程池中没有线程，等到有任务提交的时候才会创建线程
        ExecutorService executorService = Executors.newFixedThreadPool(10);

        /*
        这里进行类型转换的目的：      
        通过类型转换为 ThreadPoolExecutor，可以访问线程池的更多方法和属性，
        例如 getPoolSize()、getActiveCount() 等，由此我们就可以得到当前线程池中含有多少线程的消息。        
        注意：这种强制转换在实际使用中需要谨慎，但这里是安全的，因为 newFixedThreadPool 返回的是 
        ExecutorService 接口的实例。而ThreadPoolExecutor就是该接口的实现类。
        */
        ThreadPoolExecutor pool = (ThreadPoolExecutor) executorService;
        
        /*
        刚创建线程池时，线程池中的线程数为 0，因为 newFixedThreadPool 的初始线程池不会立即创建线程，
        而是等任务提交后才创建线程。
        */
        System.out.println(pool.getPoolSize());//0

        executorService.submit(()->{
            System.out.println(Thread.currentThread().getName() + "在执行了");
        });

        executorService.submit(()->{
            System.out.println(Thread.currentThread().getName() + "在执行了");
        });

        /*
        提交了两个任务，线程池为这两个任务创建了两个线程，因此此时 getPoolSize() 返回 2。
        线程复用：
        如果后续提交的任务数少于 10 而且又有线程空闲的话则线程池会复用已创建的线程，而不是创建新线程。
        如果提交的任务数超过 10，则多余的任务会进入等待队列。
        */
        System.out.println(pool.getPoolSize());//2
        executorService.shutdown();
    }
}

```





### 1.5 自定义线程池-ThreadPoolExecutor

#### 是什么：

除了上述通过线程池工厂类`Executors`来创建可扩容线程池和固定大小的线程池外，我们还可以通过new方法创建自定义的线程池

#### 为什么：

##### （1）为什么要创建自定义的线程池呢？

线程池工厂类`Executors` 中提供的 `newFixedThreadPool()` 和 `newCachedThreadPool()` 方法实际上是对 `ThreadPoolExecutor` 类的封装，它们可以简化线程池的创建过程同时提供很多默认的参数配置，这样已经可以适用大多数场景了，但是如果我们想要更灵活的配置参数（例如指定空闲线程的存活时间以及任务拒绝策略等）的话就得创建自定义的线程池。

#### 怎么办：

##### （1）如何创建自定义的线程池呢？

**创建线程池对象 :** 

ThreadPoolExecutor threadPoolExecutor = new ThreadPoolExecutor(核心线程数量,最大线程数量,空闲线程最大存活时间,时间单位，任务队列,创建线程工厂,任务的拒绝策略);

**本线程池的特点：**

- 线程池的初始大小为 0，线程池刚创建的时候里面一个线程也没有（不管是核心线程还是非核心线程都没有），后续提交任务的时候才创建线程。

- 线程池的参数说明：
  - **核心线程数** (`corePoolSize`)：类似于正式员工，一般情况下创建了以后始终保留在线程池中即使这些线程==处于空闲状态也不会被销毁==。
  - **非核心线程**：类似于外包员工，只有在==核心线程不够用的情况下才会创建，并且空闲下来后超过存活时间就会被销毁==。
  - **最大线程数** (`maximumPoolSize`)：线程池能容纳的最大线程数（==最大线程数 = 核心线程数 + 非核心线程数==）。当任务量超过核心线程数且等待队列已满时，线程池会创建非核心线程，但线程总数不会超过最大线程数。
  - **空闲线程存活时间**：==空闲的非核心线程会在超过指定的存活时间后被销毁==，以节省资源。其实这里严格意义上来说应该叫做非核心线程空闲存活时间，因为==只有非核心线程会被销毁==。
  - **等待队列**：
    - 核心线程不够用了，新任务会被加入到等待队列中。
    - 如果队列已满且非核心线程还没有创建完，会创建新的非核心线程来执行任务。
    - 如果队列已满且非核心线程创建完了，新任务会根据 **拒绝策略** 进行处理。
- **拒绝策略**：当任务无法提交到线程池时，线程池会采取的处理方式。
  - 默认策略为 `AbortPolicy`，即直接抛出 `RejectedExecutionException` 异常。

**代码实现 :** 

```java
package com.itheima.mythreadpool;

import java.util.concurrent.ArrayBlockingQueue;
import java.util.concurrent.Executors;
import java.util.concurrent.ThreadPoolExecutor;
import java.util.concurrent.TimeUnit;

public class MyThreadPoolDemo3 {
//    参数一：核心线程数量
//    参数二：最大线程数
//    参数三：空闲线程最大存活时间
//    参数四：时间单位（分钟、秒等）
//    参数五：任务队列
//    参数六：创建线程工厂
//    参数七：任务的拒绝策略
    public static void main(String[] args) {
        ThreadPoolExecutor pool = new ThreadPoolExecutor(2,5,2,TimeUnit.SECONDS,new ArrayBlockingQueue<>(10), Executors.defaultThreadFactory(),new ThreadPoolExecutor.AbortPolicy());
        pool.submit(new MyRunnable());
        pool.submit(new MyRunnable());

        pool.shutdown();
    }
}
```



### 1.6 自定义线程池的参数详解

```java
public ThreadPoolExecutor(int corePoolSize,
                              int maximumPoolSize,
                              long keepAliveTime,
                              TimeUnit unit,
                              BlockingQueue<Runnable> workQueue,
                              ThreadFactory threadFactory,
                              RejectedExecutionHandler handler)
    
corePoolSize：   核心线程的最大值，不能小于0
maximumPoolSize：最大线程数，不能小于等于0，maximumPoolSize >= corePoolSize
keepAliveTime：  空闲线程最大存活时间,不能小于0
unit：           时间单位
workQueue：      任务队列，不能为null
threadFactory：  创建线程工厂,不能为null      
handler：        任务的拒绝策略,不能为null  
```



#### notes：有关可扩容线程池、固定大小线程池、自定义线程池中各个参数的说明

前面我们创建过可扩容线程池和固定大小线程池但是好像没有涉及到核心线程数、等待队列等参数，那么它们有这些参数吗？

其实这些参数在所有的线程池中都有，只是前面我们使用的可扩容线程池和固定大小线程池中将这些参数提供了默认值并且封装好了，而现在自定义的时候需要我们自己去定义这些参数。

| 非核心线程数：创建了以后空闲时会被销毁（类似于外包员工雇佣了也会被开除） | 无限制（最大线程数为 `Integer.MAX_VALUE`）                   | 0                                                            | 自定义                                                       |
| 最大线程数=核心线程数+非核心线程数                           | 无限制（最大线程数为 `Integer.MAX_VALUE`）                   | 创建时给定的形参中的线程池大小                               | 自定义                                                       |
| 空闲线程存活时间（其实==严格意义为非核心线程空闲存活时间==，因为核心线程是不会被销毁的） | 60秒                                                         | 无意义（因为没有非核心线程）                                 | 自定义                                                       |
| 等待队列                                                     | 无，当有新任务提交时会先找空闲线程如果没有的话直接创建新的线程 | 有，当现有的线程满了又有新任务提交时会进入等待队列中等待线程空闲，如果等待队列也满了会采取默认的拒绝策略 | 有，当有新任务提交时会先找核心线程，核心线程也满了会找等待队列，等待队列也满了会找非核心线程，非核心线程也满了会采取拒绝策略 |

这里其实三种线程池关于等待队列的应用逻辑都是一样的，先找核心线程再找等待队列最后找非核心线程，无非就是可扩容线程池没有核心线程，固定大小线程池中没有非核心线程才导致现在的结果。





### 1.7 线程池-非默认任务拒绝策略

RejectedExecutionHandler是jdk提供的一个任务拒绝策略接口，它下面存在4个子类。

```java
ThreadPoolExecutor.AbortPolicy: 		    丢弃任务并抛出RejectedExecutionException异常。是默认的策略。
ThreadPoolExecutor.DiscardPolicy： 		   丢弃任务，但是不抛出异常 这是不推荐的做法。
ThreadPoolExecutor.DiscardOldestPolicy：    抛弃队列中等待最久的任务 然后把当前任务加入队列中。
ThreadPoolExecutor.CallerRunsPolicy:        调用任务的run()方法绕过线程池直接执行。
```

注：明确线程池最多可执行的任务数 = 队列容量 + 最大线程数

**案例演示1**：演示ThreadPoolExecutor.AbortPolicy任务处理策略

```java
public class ThreadPoolExecutorDemo01 {

    public static void main(String[] args) {

        /**
         * 核心线程数量为1，最大线程池数量为3,任务容器的容量为1,空闲线程的最大存在时间为20s
         */
        ThreadPoolExecutor threadPoolExecutor = new ThreadPoolExecutor(1 , 3 , 20 , TimeUnit.SECONDS ,
                new ArrayBlockingQueue<>(1) , Executors.defaultThreadFactory() , new ThreadPoolExecutor.AbortPolicy()) ;

        // 提交5个任务，而该线程池最多可以处理4个任务，当我们使用AbortPolicy这个任务处理策略的时候，就会抛出异常
        for(int x = 0 ; x < 5 ; x++) {
            threadPoolExecutor.submit(() -> {
                System.out.println(Thread.currentThread().getName() + "---->> 执行了任务");
            });
        }
    }
}
```

**分析上述任务的执行流程：**

我们提交了 5 个任务，因此线程池会按如下方式处理这些任务（**这里我们不考虑当一个任务提交时，前面执行任务的线程会空闲下来的情况**）：

1. **任务1**：提交给线程池，线程池中有一个核心线程可用，任务1会由 `pool-1-thread-1` 处理。
2. **任务2**：提交给线程池，任务2会进入等待队列（由于任务队列的容量为1，且核心线程池只有1个线程，等待队列可以容纳一个任务）。
3. **任务3**：提交给线程池，线程池已经有一个核心线程在执行任务1，任务2在队列中等待，因此，任务3会被分配给一个 **非核心线程**，假设是 `pool-1-thread-2`。
4. **任务4**：提交给线程池，任务4会被分配给另一个 **非核心线程**（假设是 `pool-1-thread-3`），因为线程池中已经有了 `pool-1-thread-1` 和 `pool-1-thread-2` 两个线程在运行任务1和任务3。
5. **任务5**：提交给线程池，但此时线程池已经达到了最大线程数（3个线程），并且等待队列已经满了。根据 `AbortPolicy` 的拒绝策略，任务5会被拒绝并抛出 `RejectedExecutionException` 异常。因此，**任务5不会执行**。
6. **任务2**：任务2在等待队列中等待，直到线程池有空闲线程（`pool-1-thread-1` 执行完任务1），任务2就会被执行，输出应该为 `pool-1-thread-1---->> 执行了任务`。（这里的空闲线程一定是`pool-1-thread-1`吗？如果是在多核`cpu`系统中是的，如果是在单核`cpu`系统中则不一定得看每个线程分布的时间片，但是这里就假设是`pool-1-thread-1`吧）

**控制台输出结果**

```java

pool-1-thread-2---->> 执行了任务
pool-1-thread-3---->> 执行了任务
pool-1-thread-1---->> 执行了任务
```

控制台报错，仅仅执行了4个任务，有一个任务被丢弃了

                //判断，共享数据是否到了末尾（已经到末尾）

                BigDecimal prize;
                if(count == 1){

                }else{

                    double bounds = money.subtract(BigDecimal.valueOf(count-1).multiply(MIN)).doubleValue();
                    Random r = new Random();
                    //抽奖金额
                    prize = BigDecimal.valueOf(r.nextDouble(bounds));
                }
                //设置抽中红包，小数点保留两位，四舍五入
                prize = prize.setScale(2,RoundingMode.HALF_UP);
                //在总金额中去掉对应的钱
                money = money.subtract(prize);
                //红包少了一个
                count--;
                //输出红包信息
                System.out.println(getName() + "抽中了" + prize + "元");
            }
        }
    }

需求：

​	在上一题基础上继续完成如下需求：

​	在此次抽奖过程中，抽奖箱1总共产生了6个奖项，分别为：10,20,100,500,2,300

​		最高奖项为300元，总计额为932元

public class MyCallable implements Callable<Integer> {

    ArrayList<Integer> list;

    public MyCallable(ArrayList<Integer> list) {
        this.list = list;
    }

    @Override
    public Integer call() throws Exception {
        ArrayList<Integer> boxList = new ArrayList<>();//1 //2
        while (true) {
            synchronized (MyCallable.class) {
                if (list.size() == 0) {
                    System.out.println(Thread.currentThread().getName() + boxList);
                    break;
                } else {
                    //继续抽奖
                    Collections.shuffle(list);
                    int prize = list.remove(0);
                    boxList.add(prize);
                }
            }
            Thread.sleep(10);
        }
        //把集合中的最大值返回
        if(boxList.size() == 0){
            return null;
        }else{
            return Collections.max(boxList);
        }
    }
}
